> 本报告用 `diff` 实测数据写就，每条结论都有对应文件/行号背书。后续 commit / PR review 按"目标 → 改动 → 验证"四段式推进。

### 0.2 这次重构真正解决的痛点

1. **协议飘移**：`Beat`/`WsEvent`/`ContinueMode` 在 server 与 web 各写一份，shape 早已不一致
2. **巨型组合根**：`stream.ts` 一个 291 行文件混合了状态机 + Director 实例化 + GenQueue 装配 + Provider 构造 + 402 余额判断 + 连续失败停机
3. **错误处理硬编码**：`queue.ts` 用 `instanceof ApiError && httpCode === 422` 判改写触发条件；`stream.ts:128` 用 `err instanceof ApiError && err.httpCode === 402` 判余额致命——加新 Provider 就要改这些文件
4. **Mock 文本生成靠字符串判别分支**：`opts.system?.includes('主播会提供一段剧情梗概')`——靠 system prompt 字面量决定调 splitter 还是 continuer
5. **Director 续写模式在签名里就堵死了**：`ContinueMode = 'ai' | 'suggest' | 'crowd'` 已声明但 `'ai'` 是写死的 if/else
6. **HTTP 路由和 Provider 装配混在一起**：`api.ts` 191 行同时管 session/start/stop/clips/SPA fallback + new MiniMaxClient()

### 1.3 M1 的边界

| 已落地 | 缺 |
|---|---|
| 单条直播流：splitter → GenQueue → PlayoutEngine → RtmpPusher → SRS/HLS | 想同时跑两条流？做不到（state/queue 全在 LiveStream 实例上，没有 streamId 维度的隔离） |
| MOCK 模式：免 Key 端到端跑通 | 但 MOCK 走的路径跟真实 API 不一样，依赖 `system.includes(...)` 这种 hack 切换 |
| 续写器：`'ai'` 模式（Director → continueStory → 文本模型） | `'suggest'` / `'crowd'` 模式在类型里声明但无实现 |
| 首帧续接：`FrameLinker` 抽末帧 → mm_file:// | 但 `GenQueue` 拿到的是 `mm_file://{file_id}` 引用而非本地路径，跨 Provider 时签名不一致 |
| 推流：`RtmpPusher`（生产）+ `NullPusher`（本地验证） | 真正上线才发现 `routes/stream.ts` 走的是 `pushFactory` 间接构造，缺 `ffmpeg`/`ffprobe` 时其实只挂了个空壳 |
| WebSocket：双向转发 `hub.bus(roomId)` 的 6 类事件 | inline 写在 `index.ts:27-81`，跟 http 创建混在一起 |

#### B. 巨型组合根拆成 4 层 DI

**起点**（`server/src/stream.ts:49-291`）：一个 `LiveStream` 类做了所有事
```ts
class LiveStream {

  private state, phase, errorMsg, beatViews, clipViews, shotIndex
  // ② 组件持有
  private queue!: GenQueue
  private playout!: PlayoutEngine
  private pusher!: Pusher
  private director: Director | null = null
  // ③ start() 里直接装配：
  //    - splitScript(text, script)
  //    - new PlayoutEngine()
  //    - pushFactory(playout)
  //    - new GenQueue(video, linker, {onClipReady: ...}, {concurrency, maxRetries, rewritePrompt})
```

#### C. 错误处理从 `instanceof ApiError` 改为 `ErrorPolicy` 注入

**起点**（4 处 `instanceof ApiError`）：
- `stream.ts:128`：`err instanceof ApiError && err.httpCode === 402` → 致命
- `queue.ts:121`：`this.isRetryable(err, job)` 内又 `err instanceof ApiError`
- `queue.ts:124`：同上，再用 `err.httpCode === 422` 判改写
- `video.ts:85`：`!(e instanceof ApiError) || [429,500,502,503,504,529].includes(e.httpCode)` 判轮询重试

**终点**：`ErrorPolicy.classify(err): 'fatal' | 'retryable' | 'swallow'`

```ts
// factory/providerFactory.ts:55-71
export function makeDefaultErrorPolicy(): ErrorPolicy {
  return {
    classify(err: unknown): ErrorSeverity {
      if (err instanceof ApiError) {
        if (err.httpCode === 402) return 'fatal'         // 余额致命
        if ([429,500,502,503,504,529].includes(err.httpCode)) return 'retryable'
        return 'swallow'                                  // 422 触发改写
      }
      return 'swallow'
    },
  }
}
```

`GenQueue` 现在只调 `this.opts.errorPolicy.classify(err)`，完全不知道 `ApiError` 长什么样。新增 Provider（jimeng）只要给它写一个 `JimengErrorPolicy` 就行。

#### D. Director 拆出 Strategy

**起点**（`story/director.ts:21-63`）：
```ts
export class Director {
  constructor(state, provider, queue, playout, opts) { ... }
  // loop 里直接调 continueStory(provider, state) 写死 ai 模式
}
```

**终点**：
- `Director` 只做调度循环，构造时注入 `strategy: DirectorStrategy`
- `AiDirectorStrategy` 是默认实现（在 `story/strategies/ai.ts`）
- `SuggestDirectorStrategy`、`CrowdDirectorStrategy` 是占位 stub，等二开 P1/P3 接入

`ContinueMode = 'ai' | 'suggest' | 'crowd'` 终于从"签名里挂着但永远只走 ai"的伪选项变成"真能换的策略"。

#### F. Mock 文本生成器消除 string-match

**起点**（`providers/text.ts:67-68`）：
```ts

  const isSplitter = opts.system?.includes('主播会提供一段剧情梗概') ?? false
```

```ts
setPlan(premise: string): ReturnType<typeof buildMockPlan> {
  this.plan = buildMockPlan(premise)
  this.continuedBeats = 0
  return this.plan
}
async complete(opts) {
  if (premiseMatch) { const plan = this.setPlan(premise); return JSON.stringify(plan) }
  // 否则走 continuer：用 plan.characters/entities 生成

```
外加 `extractProtagonist(text)` / `extractEntities(text)` 两个工具函数，让 mock 从梗概文本里抽主角/实体（不再硬编码"阿光"）。

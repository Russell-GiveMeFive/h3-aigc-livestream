## 二、功能 1：抖音弹幕接入

### 接入路径
抖音没有公开弹幕 WebSocket，只有**两条路**：

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A. 抖音开放平台回调**（推荐） | 官方、合规、稳定 | 需要企业资质 + 签约；需要主播**先推流到自己的抖音号** |
| B. 浏览器自动化抓 WebSocket | 无需资质 | 违反 ToS、不稳定、Cookie 易失效 |

**本项目必须是方案 A**：主播在自己的抖音号开播，用第三方推流（OBS）把本项目的 HLS/视频源推到抖音；抖音通过 webhook 把弹幕/送礼回推给我们。

### 改动文件
- 新增 `server/src/danmaku/gate.ts`：弹幕/打赏统一入口抽象
  ```ts
  interface DanmakuSource {
    name: string
    start(roomId: string): Promise<void>   // 启动接收
    stop(): Promise<void>                   // 关停
  }
  ```
- 新增 `server/src/danmaku/douyin.ts`：
  - `verifyDouyinSignature(req)` —— 抖音回调签名校验
  - `parseDanmakuEvent(payload)` —— 弹幕 `live_comment`
  - `parseGiftEvent(payload)` —— 礼物 `live_gift`
- `server/src/http/api.ts` 注册：
  - `POST /api/douyin/callback` —— 接收 webhook
  - `POST /api/douyin/bind` —— 主播绑定抖音 room_id 与本项目 room_id
- `server/src/stream.ts`：把外部事件桥接到 `bus.emit('danmaku', { user, text, ts, source: 'douyin' })`

### 关键问题：抖音回调域
抖音回调 URL 必须是公网 https。开发期用内网穿透（frp/ngrok），生产期配服务器域名。弹幕用户 `user` 用 `nickname` 占位，id 用 `open_id`。

## 三、功能 2：弹幕剧情工作台 + 自动续写

这是最值得做的一块，要做扎实分两步走。

### 步骤 A：弹幕相关性过滤

**最便宜的过滤信号已经在 `splitter.ts` 做好了**：剧本生成时输出 `entities: string[]`（10-20 个剧情实体词），这是免费的相关性判别器。

```ts
// server/src/danmaku/filter.ts
export function scoreRelevance(danmaku: string, entities: string[]): number {
  const hits = entities.filter(e => danmaku.includes(e)).length
  const lenScore = Math.min(danmaku.length / 12, 1)  // 太短通常是"666""来了"
  return hits * 0.7 + lenScore * 0.3
}
```

候选弹幕（命中 ≥1 entity **或** 长度 ≥10 + 含动词）→ 进工作台。

为了过滤"666""好看"这类噪声，第二道关用 M3 批量判别：攒 10 条候选 → 一次 `complete()` 让 M3 给每条打 `related: bool` + `topicHint`。这一步可以异步、错峰跑。

### 步骤 B：工作台 + 触发续写

```ts
// server/src/danmaku/workbench.ts
class StoryWorkbench {
  private buffer: Danmaku[] = []              // 攒的候选
  private readonly threshold = 5              // 可配置
  private readonly state: StoryState
  private readonly director: Director
  private readonly text: TextProvider

  push(d: Danmaku): void {
    if (this.buffer.length >= this.threshold) return  // 已攒够等生成
    this.buffer.push(d)
    if (this.buffer.length >= this.threshold) void this.flush()
  }

  async flush() {
    const batch = this.buffer.splice(0)
    const beat = await continueStoryFromDanmaku(this.text, this.state, batch.map(b => b.text))
    this.director.injectBeat(beat)   // 新加的 Director API
  }
}
```

`Director.injectBeat(beat)` 是新增方法，等价于内部 `continueStory()` 拿到 beat 之后做的逻辑（push 到 state、emit beat、加 queue），只是触发源不同。

`server/src/story/continuer.ts` 新增：

```ts
export async function continueStoryFromDanmaku(
  provider: TextProvider,
  state: StoryState,
  danmakus: string[],
): Promise<Beat>
```

system prompt 差异：保留原 `CONTINUE_SYSTEM` 全部约束，再加一句
> "以下是观众弹幕，请把它们合理融入下一拍剧情，保持叙事连贯，不要生硬堆砌。"

### 前端新增：剧情工作台面板（`web/src/components/StoryWorkbench.tsx`）

位置：放在 `StreamerPage` 右侧栏（"各幕剧本"上方）

内容：
- **缓冲条**：当前已攒 `N/5` 条，绿色 = 已攒够
- **候选弹幕列表**：每条带"丢弃"按钮（管理权给主播）
- **触发结果**：触发生成的 beat summary + 时间戳
- **手动触发按钮**："立即用 N 条生成下一拍"（强制绕过阈值）

通过 WebSocket 推 `workbench_update` 事件（加到 `RoomHub` 的 events 列表）。

## 四、功能 3：即梦 CLI Provider + 前端适配

### 接口适配（核心 50 行代码）

```ts
// server/src/providers/jimeng.ts
export class JimengHttpVideoProvider implements VideoProvider {
  readonly name: string
  constructor(
    private opts: {
      baseUrl: string       // 火山引擎 API 网关
      apiKey: string
      model: string         // jimeng-3.0 / jimeng-2.1
      resolution: string    // 480p / 720p / 1080p
      ratio: string         // 16:9 / 9:16 / 1:1 / 4:3
      duration: number      // 5 / 10
      pollIntervalMs: number
      cacheDir: string
      onLog?: (msg: string) => void
    }
  ) { this.name = `Jimeng/${opts.model}` }

  async generate(shot: Shot, opts: VideoGenOptions): Promise<VideoGenResult> {
    const res = await fetch(`${this.opts.baseUrl}/submit`, {
      method: 'POST',
      headers: { Authorization: `Bearer ${this.opts.apiKey}` },
      body: JSON.stringify({
        model: this.opts.model,
        prompt: shot.prompt,
        first_frame: opts.firstFrame, // 上传图片后返回的 url/id
        resolution: this.opts.resolution,
        ratio: this.opts.ratio,
        duration: this.opts.duration,
      })
    })
    const task = await res.json()
    const mp4Url = await pollUntilDone(task.id)
    const localPath = path.join(this.opts.cacheDir, `${task.id}.mp4`)
    await download(mp4Url, localPath)
    return { localPath, duration: this.opts.duration }
  }
}
```

**首帧续接**：即梦的图生视频通常要先调用 `uploadImage` 拿到 `image_id`，写 `JimengFrameLinker extends FrameLinker`。

**CLI 变体**：`JimengCliVideoProvider` 用 `execFile('jimeng', ['generate', '--prompt', ...])`，适合跑在用户本地有 CLI 的场景。

### Provider 工厂

## 五、功能 4：打赏驱动剧情走向（规划）

### 接入

`server/src/danmaku/douyin.ts` 同时解析礼物事件 → 注入 `bus.emit('gift', { user, giftName, count, value, text })`。

### 三档打赏 → 剧情影响

| 价值区间 | 影响 |
|---|---|
| 小礼物（< 10 抖币） | 仅日志，不参与剧情 |
| 中礼物（10-100） | 进 `StoryWorkbench.buffer` 当作 1 条"高优先级"弹幕 |
| 大礼物（>100 / 100+） | `Director.injectPlotTwist(user, giftName, count)` —— 注入一个剧情支线，**下一次 `continueStory` 时作为附加 system prompt** |

### 改动

- `Director` 类加 `pendingTwists: PlotTwist[]` 队列
- 每次 `continueStory()` 调用前，把 `pendingTwists` 拼接到 system prompt 末尾，调用后清空
- 主播端 `StreamerPage` 显示"当前待生效支线 N 条"，可预览、可丢弃

**未来扩展**：与抖音 `live_gift` 一起支持"礼物附言"（用户送礼时可带一句文字），把附言作为剧情指令正文，权重最高。

## 六、实施顺序建议

| 阶段 | 内容 | 风险点 |
|---|---|---|
| **P0** 即梦 Provider | 跑通"即梦生成视频 → 入推流链路" | 即梦 API 文档/鉴权；时长离散 |
| **P1** 前端设置面板 | 解耦 provider 选择；后端 API 兼容老请求 | 状态类型扩展 |
| **P2** 弹幕剧情工作台 | 工作台 + Director.injectBeat + 弹幕过滤 | M3 调用频率、成本 |
| **P3** 抖音回调接入 | webhook + 签名 + 桥接到 bus | 公网域名 / 抖音资质 |
| **P4** 打赏驱动剧情 | 礼物事件 + PlotTwist 注入 | 同 P3 |

P0、P2 可并行先做（不依赖抖音回调）。P3、P4 必须等抖音回调跑通。
